# 合成接口契约审查

对照 `use-fixtures/api-old.json` 与 `api-new.json`，应用本轮由 Jev 选中的
`api-design-reviewer` 公开指导及其三份原始脚本。没有调用业务接口或修改输入。

实际工具输出：12 条 lint 提示，6 条 breaking change，综合 45.43 / F。
这表示审查发现了测试中的缺陷，不表示接口达到发布标准。

1. 删除原本可用的 `page` 查询参数。旧分页调用失去契约依据。
2. 新增必填 `cursor`，原先不带参数的请求不再满足声明。
3. 200 响应数组元素删去 `name`，使用该字段的客户端不兼容。
4. `id` 从 integer 改为 string，旧类型校验和解析需要调整。
5. 400 错误响应从契约移除。
6. 500 错误响应从契约移除。以上两项是声明缺口，不能推断服务实际不再返回错误。

`/getUser` 使用动作式、大小写混合的命名，与 `/users` 不一致。
两个操作都缺少明确错误响应；分页也缺少起始游标的获取办法和结束条件。

建议先保留旧参数、旧字段和旧类型，另开明确的版本边界引入新契约；为旧客户端
安排迁移期，明确 cursor 的首请求和下一页语义，并恢复统一错误响应文档。
当前从 1.0.0 标成 1.1.0 并不能解决上述兼容性问题。只提交建议，没有实施迁移。

原指导的三个示例都使用 `-o`，实际脚本只支持 `--output`。首次三条命令均被
参数解析拒绝，没有生成输出；保留失败记录后改用脚本明确支持的参数，三个工具
才实际完成。breaking 检查与 B 级门槛返回 1 是发现预设缺陷的正常拒绝结果。
因此这项记为“经 Agent 调整参数后完成”，不计为原指导直接运行成功。
