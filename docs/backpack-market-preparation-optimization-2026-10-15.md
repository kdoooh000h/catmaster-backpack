# 市场准备阶段优化与失败项续测

本轮基线为同日的 `6cd2a8b` 市场目录候选版本。保留来源 → 用途 → 能力的两到三层目录、默认目录 0.1 与最终适配至少 0.7 的门槛；没有截断完整指导来换取更低消耗。

## 确认的问题与修改

旧版包级排序可复用，包内 Skill 排序却在每次否决后重新请求。旧审查记录有 14 次包内预选、18 次完整核验；下载的 74 份入口内容互不相同，不能把这 18 次都称为“相同全文重复”。真正的浪费是重复排序，以及在检查其他插件之前深入一个包的长尾。

现在包内也复用同一次 Jev 返回的完整顺序，零概率尾部保留。各包先检查最有希望的一个组件，再轮流检查暂存的其余组件；暂存队列仅限当前准备调用，原包字节、需求、完整核验门槛和安装/授权检查不变。一次找到可用组件后只授权该组件。没有找到时仍受原包数、每包 16 个组件和准备时间预算约束；未遍历完不代表没有正确能力，也不能据此保证所有需求的语义召回。

同一已验证组件的连接后读取继续复用原有完整核验回执，并重新核对作用域、授权、包完整性与当前门槛。本轮没有增加跨需求的正结果缓存。绑定指导返回一条范围提示：先完成用户要求的产物及检查，再考虑可选扩展；原指导全文保持完整。

## MCP 读取诊断

旧代码每次只等 12 秒，再重发一次，共用 26 秒分页期限。本机匿名 HTTPS 探针得到两个成功搜索响应：时区 29.157 秒、记忆 22.635 秒；两次 TLS 建立分别约 0.54 秒，时间主要花在等待首字节。主页 1.108 秒、健康检查 0.810 秒成功，环境中未设置 HTTP/HTTPS/ALL proxy 变量。

因此短超时会取消本可成功的慢请求，这是已确认的本地缺陷。额外完整目录探针在 35.03 秒仍超时，说明上游延迟存在波动。改为每页最多 45 秒、全部查询/分页共用 90 秒，单次请求不自动重发；仍拒绝重定向、无效 TLS、超量/不完整候选集，完整成功查询才缓存。慢失败的等待上限会增加，这是换取真实慢响应的明确取舍。

[官方问题记录 #1252](https://github.com/modelcontextprotocol/registry/issues/1252)的维护者说明过目录扫描造成的数据库拥塞，并建议较长超时；[官方 API](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/api/official-registry-api.md)使用游标分页。该记录支持排查方向，不证明本轮远端慢响应的数据库根因。本机目前只定位到搜索 API 等待阶段，没有服务端追踪权限。

## 网页超时诊断与计时

旧题插件准备约 7.1 秒，约 55 秒取得完整指导和模板，约 258 秒写出 17,002 字节页面。剩余约 102 秒没有留下自检执行记录，360 秒预算到期。它不是插件准备占满预算；旧日志不能区分这段等待中的模型推理、生成和传输。

本轮为原生事件增加独立的接收时间记录，保留原始事件原文，不把事件间空档直接算成推理时间。原普通提示、模型 `gpt-6-astra / xhigh`、360 秒期限和最多 12 次背包调用不变。只复测旧轮失败的网页、时区、知识关系三题；周报、主题、购物车审查的成功结果不重跑。新回合的目录或页面成功也不会自动覆盖旧失败记录。

## token、时间与成本覆盖

上表时间为各题墙钟之和，含失败等待；不是整轮用户等待时间。MCP 新轮多了安装、工具选择、真实执行和结果整理，不能把它与旧轮网络失败早停当成相同工作量的性能对照。本轮三题总时长没有下降。

两项成功 MCP 完整计账合计 678,766 token，其中原生 Agent 592,968、Jev 85,798。原生输入中 541,952 token 标为缓存输入；它已包含在输入总数中，不再次相加，不能凭此推断美元费用。全流程高 token 主要来自原生 Agent 多轮携带上下文；知识关系的多工具发现/核验也消耗了 Jev token，不全是目录分类成本。

两轮网页原生 usage 都缺失，表内该题只有 Jev 下界。因此不能给出三题完整 token 降幅。三题本轮已知下界 725,385，加另计预检 47,060，**本次总已知下界 772,445 token**；还缺网页原生消耗，根 Agent 编码、工具和协调消耗未计入，美元费用不可观测。诊断仅增加一次插件准备预检，无额外原生重跑；匿名网络探针单独留有时间回执。

## 检查、隔离与保存

169 项相关检查通过；新回归先在旧代码失败，再在修补后通过，覆盖完整排名保留、轮流检查回到尾部、最终核验、慢请求单次等待、原事件保留与时间记录等。最终源码另补一处未在本轮原生输入触发的边界：单组件证据过大只跳过该组件，继续保留同包兄弟；每包检查额度用尽标为预算未覆盖。此补丁有回归检查，没有为其重放成功业务回合。

两个任务范围 MCP 服务均核对 PID 和数据根后正常关闭，并确认进程已退出。测试数据、回执和旧版本保留；日常连接未升级，六个受保护配置文件保持原字节。本轮末尾公开插件缓存名称比开始多了 `figma-code-workflows`、`figma-spec` 两项，其他安装记录集合相同；本任务没有调用或改写 Figma 插件，这项宿主缓存变化的来源未进一步诊断，原样保留，没有回滚他人/宿主变化。它不影响本轮三种候选的新能力判定，但不能声称全宿主能力清单完全未变。

原始日志、凭据副本、安装清单、句柄、包与数据保留在本机受限证据目录，不上传。公开统计见[结果 JSON](../benchmarks/results/backpack-market-preparation-comparison-2026-10-15.json)。这轮可保留准备阶段修补；网页仍有未解决的原生完成超时，日常安装暂不晋升为“整体更快、更省且全部通过”的版本。
