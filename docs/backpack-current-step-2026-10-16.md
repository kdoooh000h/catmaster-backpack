# 多任务终选：优先当前步骤，仍保留后续能力

原来两条终选置信度不足的需求，本次新方案均通过；旧方案重新测仍拒选。
加入六条新的多任务需求后，完整通过率从 **4/8 提升到 7/8**。
但一条新需求在两版中都于第一层漏掉后续文化设计能力，因此**尚未满足全部不遗漏的
验收条件，不升级日常版本**。当前步骤选对与后续能力保留分别计分，没有用前者替代后者。

## 只改最后一个问题

原终选问“哪个能力最符合整个需求”；当前步骤和之后必须做的步骤一起竞争一个名额。
新终选问“现在这一步最需要哪个能力”，按明确的当前重点或执行顺序判断，不按文字
出现先后判断。没有明确顺序时，不擅自编排。仅用于后续步骤的能力继续留在候选中。

代码只在最终实际发送时替换问题开头。目录问题、目录描述、原始中文需求、候选全文
和顺序、分层门槛、停止规则都不改；估算阅读成本时仍使用旧问题，避免问题长度反过来
改变目录深度。没有额外的需求摘要、任务拆解调用或边界复核。终选门槛始终为 **0.7**。
元数据不可信、引用/取消/禁止事项、选择不代表执行授权等原有约束保留。

这与按明确任务分流的通用做法一致，但收益以本地实测为准，不能由方法说明推出。
[Anthropic 的工作流说明](https://www.anthropic.com/engineering/building-effective-agents)。

## 冻结的测试范围

沿用上一轮的 376 项公开能力、207 个修正目录节点。原来两条失败需求及判分目标原样
保留，六条新需求在调用前冻结，不包含能力名称，不补固定英文摘要。新组合包括：

- 先提文化设计，但明确先规划知识库，再设计文化。
- 先提账户评分，但明确先分析公司订阅财务，再评估账户。
- 先设计研究，再规划受控文档。
- 先设计部署模板，再规划监控。
- 先设计欢迎邮件，再核算渠道利润。
- 先审查采购，再规划客服人力，最后整理知识库。

两版各做一次全新无状态选择，按题交替顺序。之前已通过的需求没有重跑。
计划上限为 112 次请求、350,000 个报告 token、360 秒，每次最多 15 秒且不重试。
传输失败、未知用量、格式错误或预算耗尽会停止整轮；语义失败保留在分母中。
只验证选择，不执行这些业务任务，也不访问真实医疗、客户或采购数据。

## 同批结果

| 指标 | 旧精简方案 | 当前步骤优先 |
|---|---:|---:|
| 当前选对且所有必需能力全程保留 | 4/8（50%） | 7/8（87.5%） |
| 当前能力达到门槛并选对 | 5/8 | 8/8 |
| 全程保留当前及后续能力 | 7/8 | 7/8 |
| 原来的两条失败项 | 0/2 | 2/2 |
| 六条新多任务需求 | 4/6 | 5/6 |
| 平均报告 token | 13,378.4 | 13,481.4 |
| 平均选择耗时 | 2.875 秒 | 2.796 秒 |
| 平均调用次数 | 4.875 | 4.875 |
| 总调用次数 | 39 | 39 |
| 总报告 token | 107,027 | 107,851 |

时间本次少 **2.77%**，token 多 **0.77%**，调用数相同；这轮主要改善选择，不构成
明显的成本优化。延迟中位数为 2.902 → 2.817 秒，单次测量不能证明稳定提速。
总计 78 次调用、214,878 token、45.387 秒，未触及预算，没有重试或漏记失败。

| 当前步骤 → 必做后续步骤 | 旧方案终选置信度 | 新方案终选置信度 | 完整通过：旧 → 新 |
|---|---:|---:|---|
| 文化设计 → 知识库 | 0.64 | 1.00 | 否 → 是 |
| 账户健康 → 公司财务 | 0.37 | 1.00 | 否 → 是 |
| 知识库 → 文化设计（反向提及） | 1.00 | 1.00 | 否 → 否：漏后续能力 |
| 公司财务 → 账户健康（反向提及） | 0.90 | 0.98 | 是 → 是 |
| 研究设计 → 受控文档 | 0.99 | 1.00 | 是 → 是 |
| 部署模板 → 监控 | 0.94 | 1.00 | 是 → 是 |
| 欢迎邮件 → 渠道利润 | 0.49 | 1.00 | 否 → 是 |
| 采购 → 客服人力 → 知识库 | 0.97 | 1.00 | 是 → 是 |

置信度是提供方返回的分数，不是校准过的真实正确概率。对照是新采样，原两条旧方案
的分数与上轮 0.61、0.38 不完全一致，历史结果未覆盖。

## 新发现的遗漏

“先做知识库，之后也必须做文化设计”中，两版均选中了当前的知识库能力，但文化
设计位于经营管理顶层目录，该目录第一层得分为 **0.16 / 0.17**，低于 **0.2**，
从第一步便丢失。这不是最终 0.7 门槛导致，也不是本次终选修改造成：两版在此之前
使用完全相同的目录逻辑。

该顶层描述只概括高管决策、业务运营和财务，没有明确列出文化、价值观和组织行为。
目录规则已经要求保留必做后续工作，因此不能直接认定缺少这条规则。当前聚焦的措辞
与顶层描述覆盖不足可能共同影响分数；本轮尚未用单因素实验确认哪项是原因。
没有临时改题、降门槛、改目录或补跑来掩盖这次遗漏。

## 核对与适用范围

实测前 8 项离线检查通过，涵盖只改终选、三步候选保留、需求顺序、估算器不变、
0.69 拒选/0.7 接受、格式及未知结果停止、用量缺失停止、不重试和既有通过题排除。
实测后核对 78 对发送/完成回执、连续调用序号、逐行判分、全部 token、冻结文件、
原始需求及候选全文。没有传输错误、未知发送或缺失用量。

源码只改终选，但模型采样使两题的两组最终候选数量不同：文化题 28/35，欢迎邮件题
81/76；其他六题的最终候选集合相同。因此完整流程对照不等于强制固定最终候选池的
单次终选对照。目录 token 为 65,329/65,174，终选 token 为 41,698/42,677。
不将微小的时间或 token 差异全部归因于问题改写。

验证时 354 个发布/配置文件不变，包含日常 0.3.73；主工作区 232 个文件、HEAD 和
Git 状态不变。另一个生命周期工作区有 3 个已快照文件发生并行变化，HEAD 未变；
本轮仅观察，未写入、覆盖或回退。没有安装、激活、私有目录或生命周期运行功能修改。

这是两个已知失败加六个实现者编写的新组合，没有独立盲测，不代表所有任务的准确率。
时间和 token 只统计 Jev 选择；主 Agent 准备分析、完整业务执行、后端模型版本及
实际金额均不可观测。新的终选修正保留在实验分支，整体“不漏后续能力”的要求仍有缺口。
