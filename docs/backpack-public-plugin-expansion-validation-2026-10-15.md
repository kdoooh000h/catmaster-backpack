# 公开插件扩展与最后一个普通需求验收

2026-10-15。购物车插件项已达到“本机未安装的新能力实际完成原任务”的判据。
此前通过的五个需求未重跑，累计跨版本覆盖从 5/6 增至 **6/6**。
本项经过一次失败和一次保留连接的续做，不是六题在一个冻结版本中全部通过。

## 范围与修复

原普通需求逐字保留：检查 `cart.py` 的实际总价错误，提供输入、预期、实际及报告，不修改原文件；金额按分、商品折扣后再加一次运费、空车无运费。需求中没有 Skill、插件、市场或 MCP 名称。原生配置沿用 `gpt-6-astra / xhigh`，后端身份和美元费用不可观测。每次独立原生 home，360 秒/12 次背包调用上限。

发现的共同问题与对应修改：

1. 管理器支持登记社区市场，调用入口却只提供 Anthropic/OpenAI 两个目录。适配器现在同时提供两个核对过的公共发布者目录，并复用用户登记的 Claude 格式市场。`wshobson/agents` 有 94 个目录条目，`trailofbits/skills` 有 44 个；这些是市场条目数，不能当作 138 个独立、全新或可用能力。适配器只扩展自身进程的公共索引，不改日常用户来源文件。
2. 每排除一个插件就重新发送整份目录。现在复用同次判断的完整候选顺序，包含零概率项；实际检查仍有上限，未查完明确保留。没有把最终 0.7 门槛降低。
3. GitHub 匿名 API 达到 60/60 限额，观察时距离重置约 1,195 秒。新增 15 分钟的完整公共目录缓存，绑定来源、仓库、提交和原时间；不延长时间或冒充最新目录。首次目录读取的明确限流只暂停该来源，可继续另一个已有有效快照的来源；不重试同一来源。其他读取/provider 错误仍停止。
4. 原生 r28 已用完整指导判断通过，读取时却将同一任务重新改写，再依次做简介筛选、完整内容排序和最终判断，最后只有 0.66。单独改为一次完整指导判断仍只有 0.54，保留为失败诊断。现在同一已准备任务可以省略 `need`，沿用原需求并复用绑定的成功校验；权限、项目、包指纹、入口内容和当前门槛仍重查。需求改变或门槛提高时重新核对完整内容。没有把低分结果改成通过。

r30 是同一任务的续做，复用 r28 的原工作区、数据和完成的接入回执；新原生会话只得到已有接入的匿名句柄，没有能力名称，普通需求文本保持一致。它没有重做发现或安装。读取请求省略 `need`，使用同一个准备需求，通过全部绑定检查，未发起新 Jev 请求。

Agent 实际读取完整指导后，运行原函数及对照用例，报告记录：

- 一个 1,000 分商品、50% 折扣、100 分运费：应为 600，实际 550，运费被折扣。
- 空车、0% 折扣、100 分运费：应为 0，实际 100。
- `2**53 + 1` 分、无折扣无运费：应为 9,007,199,254,740,993，实际少 1 分。报告明确这是超大金额边界，未宣称常规金额都有精度问题。
- 无折扣、无运费、空车无运费三个正常对照均一致；未把未规定的舍入方式或数量字段当作缺陷。

Agent 又执行了报告内嵌的验证脚本，实际输出与报告逐字一致；原 `cart.py` 内容保持不变。根评估器核对了原始需求、初始名单、完整指导返回、实际执行记录、产物和原文件。completed 使用事件已记录，started 事件缺失，保留这一追踪缺口。未据此宣称指导比 Agent 独立审查更优。

## 时间/token 的实际变化

**完整成本没有下降。** 上轮 r24 是报告正确但指导已存在，209.232 秒/200,863 token，严格失败；本轮完成链是 314.573 秒/275,183 token，分别增加 50.35%/37.00%。两次的候选目录、状态和完成阶段不同，不是冻结条件 A/B，不能把续做单项当成完整成本。

本轮加上独立诊断共 **321,251 个已知 token**，未包含根 Agent 分析、编码、普通工具和网页检查等无法统一观测的消耗，美元费用未知。原生缓存输入 211,456、未缓存输入 33,630；缓存输入已经包含在输入总数中，没有重复累加。

已实现的局部节省有直接证据：旧读取做了三次 Jev 判断，续做读取为零；续做两次背包调用总等待仅 0.133 秒。完整链的背包等待为 6.286/314.573 秒，其他 308.287 秒包含主 Agent、工具编排、命令和生成报告，不能全部算作模型推理。

续做还发生一次报告写入失败：外层 Python heredoc 与报告里嵌入的 shell 示例发生分隔符冲突，产生 `zsh: unmatched`，Agent 改用独立分隔符后写入并核验成功。重复生成报告和再次带入上下文有额外消耗，但日志不足以把它们单独分账。测试指引现已要求优先使用原生文件编辑工具，或为嵌套内容使用独立外层分隔符；按“不重复已通过”的要求，没有为该文字指引再跑一次成功任务，也没有把其预期节省说成已验证结果。
