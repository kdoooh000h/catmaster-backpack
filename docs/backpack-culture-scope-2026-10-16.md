# 第一层文化目录描述修正：原遗漏恢复，第三层仍有新遗漏

原来的“当前规划知识库、之后必须做文化设计”本次复测通过。新描述下，所有六条
需要文化能力的需求都全程保留了它；但另一条新增需求在第三层丢掉后续依赖审查能力。
整体严格通过为 **3/7 → 6/7**，尚未达到全部不遗漏，不升级日常版本。

## 改了什么

只改第一层经营管理目录的一张卡。原文概括高管决策、业务运营和财务，未直接写出
内部已有的文化能力。保留原句，再补充：把使命、愿景和价值观转成可观察行为，建立
文化准则和仪式，评估文化健康度，处理文化冲突。

这些内容来自冻结公开目录里已有的
[文化能力描述](https://github.com/alirezarezvani/claude-skills/blob/19392f7a08264ed00486a251f5b2098321771f94/c-level-advisor/skills/culture-architect/SKILL.md)，
没有加入具体测试题、指定应选答案或强制保留文化分支。目录卡从 146 增至 323 个字符。
编译函数不接收需求或答案，只更改这个节点的描述；全部 376 项成员、207 个节点、
父子关系和其他描述均不变。

两版均保留上一轮的当前步骤优先终选问题。原始需求、终选候选全文、目录门槛
0.2 → 0.3 → 0.4 → 0.45、最终 0.7、停止规则均不变，无摘要、边界复核或额外
判断调用。补足能力说明后实测覆盖和成本的做法参考
[Anthropic 的工具描述与评估建议](https://www.anthropic.com/engineering/writing-tools-for-agents)，
实际结论来自下面的本地对照。

## 测试范围与结果

只复测上一轮这一个失败项，原始需求与目标不改。新增六条组合分别为：依赖审查后做
文化、监控后做文化、欢迎邮件后做文化、部署模板后做文化再整理知识库、当前做文化
后审依赖，以及取消文化工作但仍完成部署模板和监控。包含中文、同义表达和中英文
混合，不指定 Skill 名称。最后一题检查描述扩大后是否错误选中已取消的文化能力。

七题、两版、各一次新采样，按题交替先后顺序。之前通过的需求未重跑。预先冻结上限
为 98 次请求、300,000 token、300 秒，每次最多 15 秒且不重试。全部语义失败计入
分母，未知结果、用量缺失、格式错误和预算用尽会停止整轮。

本次平均 token **增加 13.30%**，时间 **增加 8.18%**，调用数增加 6.06%。正确保留
后续工作需要继续读取原来被丢掉的分支，不能把旧版漏选带来的低成本视为同等质量。

## 逐题判断

| 当前工作 → 后续工作 | 旧目录 | 补准目录 |
|---|---|---|
| 知识库 → 文化（原失败项） | 第一层漏文化 | 通过 |
| 依赖审查 → 文化 | 通过 | 通过 |
| 服务监控 → 文化 | 第一层漏文化 | 通过 |
| 欢迎邮件 → 文化 | 通过 | 通过 |
| 部署模板 → 文化 → 知识库 | 第三层漏部署模板参考能力 | 通过 |
| 文化 → 依赖审查 | 第三层漏依赖审查 | 第三层漏依赖审查 |
| 取消文化，部署模板 → 监控 | 通过 | 通过 |

原失败项的文化所属第一层得分 **0.17 → 0.72**，跨过未改变的 0.2 门槛；最终仍以
1.00 选中当前的知识库能力，同时保留后续文化能力。监控组合题为 **0.15 → 0.93**。
文化与“墙上口号变成日常行为”的同义表达也被保留。取消题两版对该第一层均给 0.04，
没有保留或选中已取消的文化能力。分数不是校准过的真实正确概率。

三步题旧版在第三层给部署基础设施目录 0.39，低于 0.4，丢掉预先指定的 Helm 参考
能力，最后选中通用 DevOps 能力（0.75）。没有实际执行来判断通用替代是否同样胜任，
因此这里只称“参考目标未选中”，不据此声称它一定无法完成任务。新方案选中预设
参考能力，但一次目录采样不能证明所有下游变化都稳定来自描述修改。

**剩余问题发生在另一层。** “当前做文化、之后审依赖”中，两版正确选中文化能力，
却在第三层给依赖审查目录 **0.36/0.35**，低于该层 **0.4** 门槛。该目录已经写了
“审计依赖和不安全代码”，因此不能再把原因直接归结为完全没写能力；当前/后续重点、
语言表达或评分分配的影响仍需另行区分。本轮未改这层、未降低门槛、未补跑失败题。

## 核对与边界

8 项低成本离线检查通过，覆盖只改一个字段、成员和原对象不变、重复编译不重复
追加、未知目录拒绝、两版终选与原始需求相同、原门槛继续生效、错误/未知用量停止、
语义失败保留及历史需求排除。离线桩测试只验证这些机制，语义效果以本次真实 Jev
调用为准。

实测后核对 68 对发送/完成回执、连续序号、逐行判分、所有 token、冻结文件、
完整需求与候选描述。验证时 354 个发布/配置文件、主工作区 232 个文件、另一生命周期
工作区 224 个文件均与本轮开始时一致，两个工作区的 HEAD 和 Git 状态也一致。
这些是相应核对时刻的观察；未安装、激活、修改私有目录或生命周期运行功能。

这是一条已知失败加六条实现者编写的新题，没有独立盲测。只能说明本批需求的选择
和遗漏情况，不能代表所有需求准确率、真实业务执行或插件/MCP 安装情况。主 Agent
与意图入口开销、实际金额、后端模型版本和完整任务成本在对照指标中不可观测。
