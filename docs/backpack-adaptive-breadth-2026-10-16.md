# 新增 28 条跨领域测试：单任务收益扩大，多任务仍有拒选

冻结上一轮两版代码和目录后，新增 28 条需求。精简版的 **20 个新单任务全部通过**，
24 条正向需求全程保留标注的当前及后续能力，说明收益不局限于原来 14 条的目标类型。
但两版均有 **2 条跨领域多任务未达到 0.7 终选门槛**，本轮不满足全部通过的验收条件，
不能据此升级日常版本。未调整选择器、目录描述或门槛，也未重试任何失败题。

## 这次怎样避免只验证原来的题型

新测试集在选择器提交 `12cd5e3e602f32def0aef96961f678ec14e42718` 后编写，再冻结
全部输入和执行源码。相对之前的 8 条和 14 条公开测试，20 个目标能力均不重复。
覆盖全部 6 个顶层目录、14 个来源领域：软件依赖、服务监控、硬件原型、助手记忆、
部署模板、临床研究设计、专利检索规划、Apple 界面、邮件序列、邀请活动、渠道利润、
客户健康、客服人力、采购支出、企业文化、订阅财务、专注安排、团队知识库、受控
文档及可验证的助手行动凭据。所有业务素材均为虚构或演示场景。

20 条单任务各测一个新能力；4 条多任务把这些能力组成跨顶层目录的当前/后续需求；
另有 4 条引用、取消、可选未来想法和前置条件未满足的控制。语言分布为中文 10 条、
中英文混合 11 条、同义表达 7 条。需求不指定能力名称、不补固定英文摘要，答案和
来源说明仅用于本地判分，不进入模型请求。

两组均使用同一 376 项公开能力、207 个修正后的目录节点、原始终选全文与顺序。
目录门槛仍为 0.2 → 0.3 → 0.4 → 0.45，终选仍为 0.7，无边界复核。需求顺序按
固定种子打乱，每题交替两组顺序，分别发送全新无状态请求。既有选择与执行器全部复用。

这是实现者编写、测试前冻结的新题，**不是独立盲测或真实用户随机样本**。不声称已
排除一切过拟合；参考目标的遗漏及当前首选是否正确是本轮具体判分对象。

一条引用控制题存在事后发现的措辞歧义，见下节；不能把全部准确率差异都当作确定
收益。主表仍保留原判分及全部失败，没有改写答案、重跑或删题。

精简版平均 token 降低 **34.75%**，平均时间降低 **20.48%**，调用降低 **11.36%**。
只看 24 条正向需求，完整通过为 21/24 → 22/24，token 降低 33.71%，时间降低
19.74%。作为事后成本核对，在双方均通过的相同 24 条中，token 仍降低 35.50%，
时间降低 22.69%；该子集不替代主表的全部分母或准确率。

平均延迟受个别长调用影响，中位数仅从 4.609 → 4.548 秒；精简版在 20/28 条中
更快，每题配对的节省时间中位数为 0.790 秒。临床研究、采购审查等部分题目反而
更慢。单次测试不能证明固定的速度提升幅度。

两组总计 249 次调用、695,491 token、289.997 秒，低于冻结的 392 次、800,000
token、600 秒限制。所有发送都有完成回执，56 行结果完整，没有传输失败、未知
发送、缺失用量或边界复核调用。失败也全部计入时间和消耗。

## 新题发现的问题

**两条组合需求都保留了正确能力，却没有通过终选。**

| 需求 | 描述修正版置信度 | 精简版置信度 | 全程保留当前/后续目标 |
|---|---:|---:|---|
| 当前设计团队文化，随后规划 Confluence 知识库 | 0.48 | 0.61 | 两版都是 |
| 当前评估客户账户，随后分析公司订阅财务 | 0.38 | 0.38 | 两版都是 |

两版原始最高候选都是要求先处理的能力，但低于 0.7，因此返回拒选。文化组合题中，
精简版的返回权重约为文化 0.62、知识库 0.38；账户组合题中，权重分给账户健康、
业务增长总入口和订阅财务。权重不等于经过校准的真实正确率。

回执支持的判断是：问题发生在终选，不是目录丢失。整个多任务段落进入单选问题，
多个确实需要的能力仍在竞争；“当前先做什么”没有充分决定最终选择。这是下一步
可检验的原因假设，本轮没有改写需求、添加摘要或降低门槛来让它通过。

**基线另有一次明确遗漏。** 可验证助手行动凭据题中，基线在第二步给监管质量目录
0.26，低于本层 0.3，排除了 `agent-decision-receipts`，最后选择 `senior-secops`
（0.84）。精简版保留目标并以 0.99 选中。这只证明本次不同路径的实际结果，不能
凭单次采样宣称已经稳定修复该类遗漏。

**一条控制题有歧义。** `ctl_quote_domains` 写了“把一句原话保存”，同时要求只
回复已记录、不开展引文里的工作。预设答案为不选能力；基线选了 `remember`，而该
能力明确支持保存知识。因此“保存”可能触发合理的记忆需求解释，不能仅凭预设答案
断定基线误解了引文。没有事后更改原答案；单独剔除此题的敏感性分析为 **24/27 对
25/27**，只看正向任务则为 **21/24 对 22/24**。后续测试设计应消除这类歧义。

## 消耗来自哪里

累计目录卡片展示 1,429 → 814，目录调用 105 → 91，目录 token 320,279 →
174,322。终选 token 则为 100,599 → 100,291，基本持平。此次节省几乎全部来自
少读目录，未削减最终能力全文。第一层平均候选 266.9 → 215.3，仍不是只选一个分支。

## 检查和隔离

实测前 9 项相关离线检查通过：新目标/新需求、六大目录与来源领域覆盖、跨目录多任务、
禁止能力名称注入、重复题拒绝、未知结果停止、不重试、语义失败保留及小分支保留。
新测试入口只负责冻结新数据，实际运行直接复用 `slim_experiment.run`；两版选择代码
均与上一轮哈希一致。实测后核对 249 对发送/完成记录、逐行判分、输入哈希、原始需求、
终选全文、0.7 接受与拒选边界和全部 token。

实测结束后的首次核对中，354 个已知发布/配置文件不变，包含日常 0.3.73。提交后的
复核发现其中一份宿主配置发生并行变化，其他 353 个文件仍一致；未读取其配置内容、
归因给本次实验或回退该变化，原始实测核对记录保留。主工作区 232 个已跟踪或未跟踪文件、
HEAD 和 Git 状态不变。另一个生命周期工作区在测试期间有 5 个已纳入快照的文件发生
并行改动，HEAD 未变而 Git 状态改变；本轮未对该工作区写入、覆盖或回退，也不把它
记作“全工作区未变”。没有安装、激活或修改私有目录、dispatcher、生命周期运行功能。

这轮只验证能力选择，不执行 28 个业务任务，也不重新验证市场安装、插件或 MCP
调用。主 Agent 推理与协调成本、完整任务成本、后端模型版本及实际金额不可观测。
本轮保留全部结果，但精简版仍未通过“所有新题都通过”的验收，不作日常发布。
