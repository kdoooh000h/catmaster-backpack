# 目录宽度与深度试验

2026-10-15。**三层没有数学上的特殊地位，但本轮没有测出最佳层数。**
在同一份 376 项公开能力目录上比较了 2、3、4、6 层。第一版自动目录的描述
区分度不足，试验设置的前层 0.1 保留门槛又过宽，导致多数分支都保留。
增加层数没有有效缩小候选，反而增加了目录读取和调用开销。

这是有明确失败记录的初步试验，不是目录优化成功，也不是日常背包的准确率评估。
没有改动日常选择逻辑、最终 0.7 门槛、直达/常用入口或生命周期功能。

## 数学上优化的是什么

设目录共有 N 项能力，每次保留一条正确路径，每层平均有 b 个分支，末端保留 k 项，
那么理想目录层数约为 `L = log_b(N/k)`。目录加末端大约需要读 `L×b + k` 张卡片，
需要 `L + 1` 次模型调用。这里的“层”只计目录步骤，最终选具体能力另算一次。

每次请求有固定耗时和重复上下文，所以应同时考虑：

`总开销 ≈ 调用次数 × 固定开销 + 各步实际读取的描述开销`

即使单次选择更简单，增加步骤也会增加漏选机会。若各步在此前保留正确路径的条件下
都保留 98% 的正确能力，三步累计约 94.1%，六步约 88.6%；这是解释用的假设数字，
不是本轮观测，也不能把模型自报的 0.7 当成真实准确率。

真实任务可能同时需要多个分支，分类描述也可能有歧义，因此 `b` 不只是目录里排了多少
子节点，还要看模型实际保留多少节点。优化目标应是“正确能力不被过滤掉”约束下的
时间和 token，而不是固定三层、固定二叉树，或让列表看起来最短。

## 固定输入与对照

公开来源是 [claude-skills 的固定提交](https://github.com/alirezarezvani/claude-skills/tree/19392f7a08264ed00486a251f5b2098321771f94)，
包含 376 项去重能力、20 个来源分类。核对原始目录与评估目录逐项一致，保留完整描述、
ID 和顺序；压缩包 SHA-256 为 `30ce857856ee03a5940b1382e56ca1f9b209028f1e2d8087b7a71bf6705c23c9`。
只使用元数据，没有安装或执行来源代码。

原人工分类以 6 个根类和 20 个来源子类作结构基准。自动分类使用确定性的词频加权
平衡切分，目录卡片由 12 个代表词和全部来源分类组成。构树不读取测试题或标准答案。
这种廉价表示不等于语义模型生成的可靠分类描述。

后三种层数看 12 张卡片，是每一步都选对单一路径时的结构计算，不是模型测试结果。
四个“较小末端”方案复用完全相同的树和末端能力；只改变一次展开几级。
人工目录与自动目录之间同时改变了分组和描述，不能把差异只归因于层数。

所有方案使用相同的原题、目录保留门槛 0.1、最终 0.7、最多 96 个最终候选。
这是试验参数，不代表日常背包当前的前层门槛。保留多个相关分支，超限明确停止，
不截断候选、不回退全量。每阶段只调用一次，按题轮换方案顺序。

预先冻结 8 题：中文 2、同义表达 2、中英文混合 2、取消/引文控制 2。
计划上限为 200 次调用、900 秒、调用前已知用量 300,000 token。
一条正在执行的响应允许跨过 token 上限；达到上限后不再开始下一条。

## 真实观测

64 次 Jev 请求共报告 **309,129 token**，其中输入 282,248、输出 26,881。
累计各方案运行段约 64.26 秒，所有已发请求均有用量；不包含协调 Agent 的用量、
离线准备或分析时间。未测账单费用；后端模型具体修订不可观察。

达到 token 上限后停止，没有追加或重放。共同完整测过的只有 3 题：中文模型费用优化、
中文供应商评分、同义表达的集群自定义控制器。第四题应用内升级提示只完成两组。
其余混合语言、多任务及负向控制没有测到，不能说 8 题全部完成。

## 原因与已有分数复盘

以第一道费用优化题为例，人工目录六个根类的分数是 0.64、0.30、0.17、0.44、
0.22、0.16，都超过试验的 0.1 门槛。自动树的八个第一步目录分数在 0.46～0.55，
同样全部留下。六层自动树随后实际读取 2、4、8、16、32、64 张目录卡片，累计 126 张，
而不是理想单路径的 12 张。瓶颈是分支没有被排除，不是单次二选一还不够简单。

我把前层门槛设得过松，又没有在放大对照前先做“能否实际缩小”的小样检查。
因此这一轮用量主要花在重复描述几乎相同的候选集合上。它暴露了试验设计和目录表示的
问题，不能证明所有深层目录都不好。

随后只重算已有分数，没有新增模型调用：

- 门槛改按 0.3 解释时，人工两层在三题中都保留正确能力，末端仍为 207、73、143 项。
  自动两层末端较小方案仍有 325、229、319 项；四层和六层各有一题丢掉正确能力。
- 改按 0.5 解释时，自动两层末端较小方案缩到 47、53、0 项，但三题都已漏掉正确能力。
  三层和六层也都只保留一题的正确能力。

这是失败原因诊断，**不是另一次真实 A/B**。改变提供给模型的候选集合可能改变分数；
不能拿重算结果作为新门槛的准确率或时间。没有把复盘阈值部署到背包。

## 对设计的影响

允许超过三层是合理的。下一版更值得检验的是**分支自适应深度**：目录能清楚区分、
候选已少时直接进入终选；候选多且能有效区分时继续展开。是否加一层，应由实际候选
缩小量、正确能力保留和额外请求成本决定，而不是由人类习惯或整齐的树形决定。

先用少量独立题检查目录描述能否产生有效区分，再扩大深度对照。需要避免“包含很多
宽泛来源类别”的卡片；用具体操作、交付物和相邻分类边界表达子目录。不能靠提高
门槛把不准确的描述掩盖掉，也不能把本次题目调好后冒充未见过的新题测试。

[RAPTOR](https://arxiv.org/abs/2401.18059)研究树状表示和检索，
[ToolRerank](https://arxiv.org/abs/2403.06551)研究工具检索的自适应及层级排序；
[工具描述与评估实践](https://www.anthropic.com/engineering/writing-tools-for-agents)
也把描述质量和实际任务评估放在一起考虑。本轮没有复现这些方法或借用其收益数字。
