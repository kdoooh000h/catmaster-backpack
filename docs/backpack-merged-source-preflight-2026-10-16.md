# 合并市场、按用途分类的目录预检

隔离实验现在以独立 Skill、完整插件、MCP 服务为候选。市场只保存在来源信息中，
不形成查找层级。插件内部 Skill 不再拆成候选，也不计入独立 Skill 数量。
本轮只完成目录预检和本地程序检查；原五条需求的正式 Jev 准确率、时间和 token
对照尚未执行，不能据此宣称排名策略优于现方案。

此前提取出的 600 项插件内部 Skill 已从实验目录和统计中移除。旧提取记录只在本地
实验历史中保留，提取工具不进入本次提交。没有删除或修改已安装插件的任何文件。

去重完全由程序完成，不调用 Jev，也不需要人工逐项确认。相同 GitHub 仓库、固定
提交、组件路径及行为配置的插件可以合并；原生插件使用稳定包身份和观察到的版本，
不用目录每次生成的随机修订号。同名或说明相似不足以证明重复；不同版本、组件路径、
执行方式或组件覆盖配置分别保留。来源别名、所有说明版本、标签和排名观测值均保留。

真实快照中，Astronomer 同一固定实现的三个别名合为一项，另有 SAP CDS、RevenueCat
和 Vanta 各两个别名合并，合计减少五条。没有按流行程度删除不同能力。

## 分类不按市场分组

所有市场共用开发、设计、写作、数据、研究、运维、安全、经营等用途目录。
Skill、插件和 MCP 可以在同一个用途目录中出现，并保留其交付类型；指导和执行不会
因为主题相同而被当成同一种能力。选中插件后，才在该插件范围内处理其内部组件。

本轮复用发布者标签，346 个候选已归入用途目录，589 个仍待补分类。
待分类条目保持可见，不能因为没有标签而丢弃。目录编译检查全部候选的覆盖；
这些统计不表示分类语义已经全部正确，也不证明目录已经达到理想的筛选效率。

## 为什么正式对照尚未开始

1. 观察到的源记录没有可比较的排名和增长字段。Skills 正式 API 的匿名请求返回
   HTTP 401；其[官方 API 文档](https://www.skills.sh/docs/api)说明需要认证。
   本轮没有新建账号、读取或提交密钥，也没有把缺失排名当成零。
2. MCP Registry 在三分钟读取预算内保存了 34 页、3,400 条记录，仍有下一页，随后
   读取超时。这部分不完整结果没有进入选择池；不能将上表的一项参考 MCP 冒充
   整个 MCP 市场。已保留分页证据，没有重新读取已完成页面或自动重试。
3. 分类尚未补齐。排名只能在满足同一操作需求的替代项中帮助选首选和备用，不能把
   同一宽泛类别的不同能力全部删到只剩榜首。

原来的五条多任务需求保持原文和顺序，最终门槛保持 0.7，当前步骤和后续必需能力
的保留要求继续适用。目录扩大后，应在同一份合并快照上同时测现方案和候选方案；
不能把旧单仓库结果直接混入新目录的时间/token 平均值。判分应预先列明需求所需的
操作和可接受替代项，不能仅凭旧仓库中的能力 ID 判断多来源能力是否正确。

## 已完成的检查与边界

20 项离线检查通过，覆盖跨市场固定实现去重、说明和别名保留、不同组件配置不误合并、
去重幂等、用途目录跨来源/类型合并、待分类保留、插件内部条目拒绝、排名不可比和
过期数据处理、后续能力保留以及最终 0.7 边界。实际快照重放得到上述 935 项目录。
这些检查不是模型准确率或插件/MCP 实际执行业务的验收。

正式对照的 Jev 选择调用和 token 均为 0，因为尚未发送；准确率、时间差和 token 差
均标为未知。源预检约 183 秒，与单次能力选择耗时不是同一个指标；主 Agent、意图
入口及健康检查的 token 没有统一计量，不包含在这两个零值中。

本轮代码、快照分析和报告均在实验工作区。日常配置/来源状态、安装能力和另一升级
工作区没有被本轮写入。没有发布新版本或修改其生命周期功能。
