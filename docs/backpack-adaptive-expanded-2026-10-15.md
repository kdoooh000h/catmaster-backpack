# 扩大其他能力测试：省消耗候选出现遗漏

2026-10-15。新增 14 条普通需求，保持上轮两套选择实现、目录和门槛不变。
原自适应通过 **13/14**，精简候选通过 **11/14**。精简候选多漏了数据质量检查和
会议行动项整理；两个方案都漏了研究摘要专用能力。**精简候选暂不满足不遗漏要求，
不能根据上一轮 16/16 的熟悉题结果替换日常版本。**

另外，预先指定四个任务做实际产物检查：三项在正确选择后完成，数据质量题因漏选
没有进入执行。这里实际应用的是所选公开 Skill 的完整指导及原始脚本，来源为已验证
的固定公开快照；没有走日常背包获取网关、市场安装或 MCP 调用。因此它验证到
“试验选择器 → 对应公开 Skill → 本地产物”，不能算插件/MCP 接入验收。

## 时间与消耗

| 全部 14 题的平均值 | 原自适应 | 精简候选 |
|---|---:|---:|
| 通过 | 13/14（92.9%） | 11/14（78.6%） |
| token | 7,051 | 5,023 |
| 选择时间 | 2.61 秒 | 2.41 秒 |
| Jev 请求 | 3.79 | 3.36 |

精简候选表面上减少 28.76% token、7.57% 时间，但含提前失败的省耗，**不能算同等
质量下的整体性能提升**。只看双方都通过的同 11 题，平均 token 为 6,671 → 5,180，
时间为 2.50 → 2.38 秒。这是事后描述性子集，不替代包含失败的总体结果。

正向题单列：原方案 11/12，精简候选 9/12；平均 token 7,942 → 5,606，
时间 2.88 → 2.66 秒。两个控制都正确拒绝。最终 0.7 门槛没有下降。

## 已定位到的遗漏位置

- **数据质量**：精简候选给第二层 engineering 目录 0.27，低于该层 0.3，
  最终所有分支被排除。原方案在同一目标目录给 0.63，最终选中目标、置信度 1.0。
- **会议行动项**：第三层含 meetings 的分支仅 0.27，低于 0.4，正确能力已丢失。
  剩余五项终选只得到 0.39 并弃选。低终选置信度是后果，不是最初原因。
- **研究摘要**：含 research-summarizer 的操作组在原方案和精简候选中分别为
  0.37、0.36，均低于 0.4。该组说明主要围绕用户、市场和产品研究，泛研究摘要
  的范围不够明确；这是待修正的分类/描述边界，不能靠终选高分弥补已删除的目标。

已确认的是实际淘汰位置和分数。精简提示改变了打分条件，但单次观测仍不能把差异
归因到某一个词或完全排除随机波动。本轮没有调参、换问法、降低门槛或重放模型来
把失败刷成通过。需要先修正这些边界，再独立检验；当前候选未晋升。

## 实际使用的三个产物

| 预定任务 | 实际使用与检查 | 结果 |
|---|---|---|
| 数据质量报告 | 选择时失败，未改用点名能力补做 | 未进入执行 |
| API 兼容性审查 | 运行所选 Skill 的 lint、breaking detector、scorecard；人工复核合成契约 | 调整示例参数后完成 |
| 发布说明与版本号 | 原始提交检查、版本计算、说明生成脚本；逐条核对提交引用 | 完成 |
| SQL 查询 | 按指导写参数化 LEFT JOIN，在只读 SQLite 连接实际查询并运行原始优化器 | 完成 |

接口 Skill 的三条 Quick Start 示例用 `-o`，快照里的脚本只支持 `--output`。
首次全部在参数解析阶段明确拒绝，没有产物或待确认副作用；保留三条错误后，根据
实际帮助信息调整参数。随后检出六处兼容性问题、12 条 lint 提示及 F 级评分。
breaking 与最低 B 级检查返回 1 是正确发现测试缺陷，不能说被审查 API 通过了验收。
这暴露了固定快照中指导与脚本接口不一致的问题，没有修改第三方 Skill。

发布说明脚本验证 5/5 提交，识别不兼容变更并建议 **1.4.2 → 2.0.0**；最终说明
补齐提交编号与迁移动作。SQL 查询得到北星 1500 分、岚 700 分、青叶 0 分，
保留零已支付订单客户；查询前后数据库字节一致。所有输入都是合成数据，没有发布、
通知、真实账户或生产数据库操作。

## 预算、复现与保护

固定使用原 376 项公开快照、207 节点树及原始最终描述，分类器代码保持上一提交
字节不变。模型只看到需求和候选，不看到答案。交替方案顺序，每阶段独立请求。
这批题是本轮新增，尚非独立评审者的盲测；写题时可以看到公开能力元数据。

预设预算：180 请求、350,000 已知 token、360 秒，单调用 15 秒，零模型重试。
实际 **100 请求、169,047 token、70.25 秒**，28 条选择结果完整；没有未知发送、
错误回执、缺失用量或预算未测题。原始请求、失败与脚本错误均保留在本机证据目录。
所有语义失败都计入分母；遇到传输错误、未知用量或预算耗尽则整体停止。

三项新离线测试覆盖失败保留、未知调用不重放和新题无能力名；上轮 28 项检查结果
在实现未变的条件下继续有效。实际产物另按输入事实、返回码、JSON 和文件哈希核对。
236 个既有发布/配置路径在本轮核对一致，日常版本与生命周期未改，其他工作未动。
