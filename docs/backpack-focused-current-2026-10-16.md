# Current-focused shortlist: lower tokens, incomplete recall and slower selection

The candidate uses **85.10% fewer tokens** on the same eight live pairs, but
warm selector time rises **23.82%**. Under a prospective, predeclared metadata
relevance reference version, success is **7/15 versus 8/15**. New-case success
falls **3/5 to 2/5**; known-primary retention and selection success fall **5/15
to 2/15**. **Do not promote this candidate to daily routing.**

These are capability-acquisition selection results, not actual task completion.
The earlier published 5/15 result is unchanged. This is a different cohort and
reference version; it cannot be presented as a direct increase from that score.

## Scope and the reference correction

The fixed catalog remains 45,325 public records (682 Skills, 628 whole plugins,
44,015 MCPs), with the same pinned local multilingual MiniLM index. Markets stay
merged, plugins stay whole, and identity deduplication remains programmatic.
No private catalogs, installer code or daily connections are changed.

This run reuses only the ten previous **strict failures**, preserving their raw
requests. All five prior passes are excluded. Six fresh ordinary needs were
written before reference inspection. Five receive defensible **metadata-level
relevance** references; software-copy localization remains an explicitly
recorded, unscored source-metadata gap. No capability name is specified in a raw
request. Source strata do not force a capability kind; implementation planning,
for example, can reasonably use a whole planning plugin.

An independent read-only review verified reference IDs, descriptions, hashes,
request text and current/later groups before calls. Prospective additions cover
frontend implementation, read-only GitHub, financial runway, debugging, current
documentation, browser interaction, papers and forecast services. This review
saw development retrieval pools, so these are **retrieval-informed reference
revisions**, not independent holdout labels. The ten old needs are development
regressions. The five new needs are withheld from ranking-method development.

Both arms use the **same new references**. A selected current capability must
belong to its frozen accepted set and receive provider `current` Choice
confidence **>=0.7**. A current equivalent must survive the final shortlist and
each later requirement must have an equivalent in the retained reservoir.
Known primary-anchor retention is a separate, stricter diagnostic. Retaining
one acceptable equivalent does not establish exhaustive recall of all relevant
capabilities. No after-call reference rescue or old-score rewrite is allowed.
Preflight uses benchmark references; production cannot detect every unknown
omission this way.

Metadata relevance does not prove every requested detail. New exception design,
map routing, project planning and REST references have explicit detail gaps;
those are held to the same broad relevance standard as the existing debugging,
weather and paper references. SDK-oriented translation guidance was not accepted
as software-copy localization guidance. The final model may still judge broad
metadata partial and abstain. None of the capabilities were installed, invoked,
or shown to produce a correct artifact.

## Causes verified before changes

The prior shared facet rules often include a later or prohibited operation:
Word formatting during debugging, a spreadsheet during browser research, email
inside a paper-search prohibition, and meeting creation in a time-conversion
prohibition. They are unreliable as exclusive current-step filters.

The semantic index embeds only each name and short description. Several entries
omit useful operational detail; the Context7 anchor, for example, says only
“Up-to-date code docs for any prompt.” Multilingual ranking also misses better
specified timezone and weather entries. Original top-three clause-by-kind
retrieval loses known targets while accumulating many unrelated candidates.
These are separate from arbitrary reference-ID omissions.

The expensive prior final asks one repeated current/partial/other question per
candidate and returns a distribution for each. A single API request can still
contain over a hundred judgments. The official
[TypeSafe primitives documentation](https://docs.typesafe.ai/primitives)
describes shared state, independent questions and structured instructions; its
[confidence documentation](https://docs.typesafe.ai/confidence) defines Choice
confidence over the supplied options. We retain the suitability semantics and
raw 0.7 threshold; prompt/context changes do not prove equal calibration.

## Local methods and rejected variant

The optional `BilingualDictionary` reads an explicit caller-owned, unmodified
[CC-CEDICT](https://www.mdbg.net/chinese/dictionary?page=cc-cedict) snapshot
(125,288 source entries, release 2026-10-16). It matches multi-character Chinese
headwords greedily, retains traditional/simplified forms and every sense in an
audit, removes classifier/reference/pronunciation boilerplate, and filters
English hint terms against catalog vocabulary. These are additive search hints,
not a sentence translation or fixed English task summary. The raw task is always
sent unchanged to Jev. CC-CEDICT is by MDBG and contributors, licensed CC BY-SA
4.0; the dictionary is not vendored into this repository or installed at runtime.
Its download hash and attribution are in the sanitized precheck artifact.

An explicit later-step marker supplies a current-focus **ranking hint**. It does
not remove any text from the actual model task. Local BM25 over name/description/
labels and dense similarity over the current hint each produce 24 per-kind
neighbors, retaining boundary ties. Reciprocal-rank fusion selects approximately
12 current candidates, expanding exact boundary ties. The original full pool
and added neighbors remain in a later reservoir. Final prompts contain complete
descriptions of shortlisted candidates, a shared current/partial/other definition,
and compact criteria. Type is a usage form, never an automatic preference.

Two low-cost variants were checked on the ten old failures. Under the same
prospective references, global RRF retains 8/10 current groups; a per-route
union with first-sense gloss queries retains only 6/10. Both retain only 2/10
original primary current anchors. The less complete per-route variant receives
no live calls. The local RRF best is selected for bounded exploration before
new-case retrieval, while remaining ineligible for daily promotion. Its known
omissions stay in the accuracy denominator and do not receive model calls.

## Measured cost and time

All **21 real requests** and **269,290 tokens** reconcile: baseline 10 calls /
229,364 tokens, candidate 11 calls / 39,926 tokens. The eligible sets differ, so
these totals are not an equal-coverage cost comparison. No errors, unknown
usage, missing receipts, retries or replay occurred.

The table uses only the **same eight needs actually sent in both arms**, with
alternating arm order and one sample per pair. Offline failures remain failures,
not successful zero-cost calls.

| Mean per live paired need | Full-pool baseline | Focused candidate | Change |
| --- | ---: | ---: | ---: |
| Tokens | 24,309.1 | 3,622 | -85.10% |
| Input tokens | 20,706.1 | 3,105.4 | -85.00% |
| Output tokens | 3,603 | 516.6 | -85.66% |
| Final candidates judged | 97.4 | 14.1 | -85.49% |
| Retained reservoir | 97.4 | 204.1 | +109.63% |
| Local retrieval seconds | 0.768 | 1.340 | +74.48% |
| Final dispatch seconds | 0.899 | 0.725 | -19.44% |
| Warm selector seconds | 1.667 | 2.065 | +23.82% |

The smaller final request saves most of the tokens and some dispatch time. The
additional dictionary/BM25/dense ranking costs more local time than dispatch
saves. Cold startup is separate: semantic model/index load 51.943 seconds,
dictionary parse 8.333 seconds, local index startup 31.039 seconds. The existing
dense index is reused; no new embeddings model or translation service is added.
The Mac has uncontrolled concurrent workload, so one run does not establish
stable latency. Main-Agent tokens/time, money and backend model revision remain
unobservable. No fixed English summary is used.

Before sends, a provisional 240k-token plan was revised to a fixed **320k**
ceiling after the measured preflight showed 21 eligible requests. The old plan
is retained locally; a byte check proves only that budget constant changed in
source, with task strings, references, algorithms and recalls unchanged. Final
limits are 30 calls, 320k tokens, 180 seconds and 20 seconds per request, with
one attempt. Actual calls and usage stay within those bounds.
