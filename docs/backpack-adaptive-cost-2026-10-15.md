# 自适应目录的消耗优化

2026-10-15。保留自适应目录，优化重复目录说明和总候选量的停止判断。
同一批 8 条普通需求各跑两轮，原自适应和优化候选均 **16/16 成功**；
12 次正向选择都保留了全部标准目标，4 次负向控制都正确拒绝启动能力。
最终门槛仍是 **0.7**。这是隔离的公开 Skill 选择测试，尚未更新日常背包。

| 每条需求平均 | 原自适应 | 优化候选 | 变化 |
|---|---:|---:|---:|
| 总 token | 9,148 | 5,046 | 减少 44.84% |
| 选择耗时 | 3.43 秒 | 3.03 秒 | 减少 11.70% |
| Jev 请求 | 4.19 | 3.31 | 减少 20.90% |
| 本批成功 | 16/16 | 16/16 | 未观察到退步 |

负向题提前结束也计入了上表。**只看实际选择能力的 12 次正向测试**，平均 token
从 10,375 降到 6,135（40.86%），时间从 3.56 秒降到 3.33 秒（6.42%），
请求从 4.50 降到 3.92（12.96%）。时间改善较小，三题的两轮平均时间略有增加；
不能承诺每题都更快，也不能把本批通过率说成所有需求的准确率。

## 消耗为什么下降

旧记录显示，单个分支不超过 8 项就暂存，可能让许多小分支累积成 55～58 项；
随后终选仍要读所有候选的完整描述。有些子目录还重复携带父目录的整个操作范围。

本次仅在新的隔离候选中改两部分：

- 缩短重复的判断提示。同一批子目录共有的父级说明只放一份，子目录保留完整的
  成员名称列表，并明确只判断本子目录涵盖的操作。父级原文没有删掉，所有最终能力
  描述和顺序保持原样。目录提示的措辞确实改变了，因此收益不只是字数压缩。
- 用**合计候选量**决定是否继续展开。总量不超过 24 项就尝试终选；超过时继续
  展开仍可细分的分支，已到末端的分支完整保留。保留原来的读取成本估计、96 项
  终选上限、六轮上限和不缩小就停止的规则，不截断候选或回退全量。

目录门槛依旧按深度为 0.2、0.3、0.4、0.45，终选至少 0.7。
程序没有按需求关键词删能力，没有改树的成员，没有固定英文摘要，也没有把标准
答案传给模型。多任务题的后续 QMS 能力每一步都必须保留，否则整次不通过。

离线在上轮完全相同的已观察目录批次上重排提示，估计请求字符减少 16.93%；
这是字符测量，不是实际 token。真实收益还来自目录打分变化与候选缩小：
两轮终选阶段用量合计从 63,051 降到 23,843 token，目录阶段从 83,310 降到 56,887。
本次把提示精简和整体停止一起测试，**没有分离两项各自的贡献**。

实际路径举例（均为本次实测）：

```text
模型费用题，优化：376 → 255 → 149 → 10 → 终选
升级提示题，优化：376 → 250 → 132 → 40 → 8 → 终选
```

模型费用题原方案两轮终选分别为 66、51 项；优化后都是 10 项。
升级提示题原方案两轮都是 55 项；优化后都是 8 项。完整描述只在终选时读取。

## 同题对照与波动

沿用上轮固定的 376 项公开目录、原始完整描述和 8 条原题。来源为
[claude-skills 固定提交](https://github.com/alirezarezvani/claude-skills/tree/19392f7a08264ed00486a251f5b2098321771f94)。
树仍是 207 节点、最深五层、静态覆盖 376/376。两轮交替两方案的执行顺序，
每一步发独立、无历史的请求，不跨方案复用答案或重放已结束请求。

| 原始需求 | 原方案时间 / token | 优化后时间 / token |
|---|---:|---:|
| 中文模型费用优化 | 4.42 秒 / 16,068 | 4.58 秒 / 7,220 |
| 同义表达的集群控制器 | 4.66 秒 / 9,152 | 4.39 秒 / 7,169 |
| 同义表达的应用内升级提示 | 3.62 秒 / 14,161 | 3.70 秒 / 7,997 |
| 中英混合：先 Jira、后 QMS | 3.55 秒 / 10,641 | 3.38 秒 / 6,888 |
| 中文供应商评分 | 2.74 秒 / 7,835 | 1.99 秒 / 4,290 |
| 中英混合财务模型 | 2.34 秒 / 4,393 | 1.92 秒 / 3,248 |
| 引文只记录，不执行 | 3.05 秒 / 5,500 | 0.76 秒 / 955 |
| 取消旧需求，不执行 | 3.03 秒 / 5,431 | 3.48 秒 / 2,598 |

每行是两轮平均。所有题目的平均 token 都下降。第一轮整体为 9,354 → 5,085，
第二轮为 8,941 → 5,006；目前不是单条异常值撑起全部结果。

仍然观察到 53 组相同输入中 47 组分数有变化，7 组跨过保留门槛：原方案 6 组，
候选 1 组。候选多任务题终选为 15 或 20 项，均选中 Jira 且保留后续 QMS。
两轮只能说明这批熟悉题目的初步稳定性，没有统计显著性或新需求泛化结论。

## 完整性、预算和保护

先通过 28 项相关离线测试，再冻结输入、代码、预算和顺序。两个负向控制先跑，
之后是六条正向需求；候选一旦漏目标、选错、弃选、误触发或不可用就停止。
预算固定为最多 160 请求、260,000 已知 token、300 秒，单请求最多 15 秒，零重试。

实际完整跑完两轮，共 **120 请求、227,091 token、103.29 秒**，其中输入 201,345、
输出 25,746。没有错误回执、未知发送、缺失用量或未跑题目，没有追加预算。
这些数字只包含选择器请求及该运行段；主 Agent 的准备、分析和报告不在内，
账单费用与后端模型修订未观测。没有重复执行已通过的业务任务。

本轮起始保护清单的 121 个发布/配置路径在结束时一致。另一对话独立升级了
`0.3.72+consultation.20261015`；收到通知后也保存了该版本 115 个文件的只读校验清单。
本任务只改实验源码和报告，没有改日常连接、正式目录、生命周期、安装目录或 main。
旧版缓存和未提交的其他工作均未处理。新版本保护清单在保存上传后再次核对。
