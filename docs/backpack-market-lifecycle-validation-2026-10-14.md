# 背包能力使用规则与普通需求复测

2026-10-14。已实现“独立 Skill 按需读取；插件先接入背包；MCP 先安装依赖或登记连接，再调用”。
本轮保留所有失败，累计有 **3/6 个独立需求** 使用此前未安装的新能力完成任务：周报、交互页面、时区换算。
这是多次修复后的覆盖结果，不是一轮冻结版本的 50% 成功率。三类各有一个成功样本，不能推广为市场全部可用。
日常安装版未升级，现有能力和连接未改动。

## 修改及实际证据

1. **明确三类生命周期。** 独立 Skill 可直接取得选中的指导和资源，缓存不等于安装宿主插件。
   插件先在背包安装并注册受支持的组件；本地 MCP 先安装固定版本依赖，远程 MCP 先保存连接。
   安装、工具选择、业务执行、任务完成分别记录。没有把接入成功计为通过。
2. **插件外部来源。** 支持市场声明的公共 GitHub 仓库及子目录，固定包提交，保留市场提交与包提交。
   按选中市场读取对应宿主清单，避免将同仓库其他宿主清单误判成冲突。
   真实代码审查样例已能下载并识别外部包，但其原生 commands/agents 与 CLI 登录要求仍不能由本适配器执行。
   未将缺少原生能力的部分安装报告成完整插件。页面插件实际接入、取到模板并完成任务。
3. **MCP 选择分阶段。** 来源/安装候选使用目录阈值（本次 0.1），带上安装条件，但不提前要求市场简介证明全部运行能力。
   接入后查看实际工具描述和完整输入结构，最终至少 0.7，或采用更严格的配置。
   最终判断的是“是否可靠完成任务需要的一步”，不是“一个工具是否包办全部需求”。
   `none`、不确定和超大结构仍明确停止；调用权限和最终结果另行核验。
4. **名称索引查询。** 提示先用一个精确功能词；多词 OR 会扩大结果。
   某词已有超过 192 个有效候选时提前返回“范围过大”，不继续读剩余页，也不从截断前缀选择。
   市场读取的超时仍会出现，本轮未证明可用性保证；没有使用镜像或关闭 TLS 校验。
5. **真实 npm 启动修复。** 新时间服务已安装却初始化失败。直接启动同一包的真实 bin 能列出工具，
   确认其主模块判断与 npm 快捷入口的符号链接不兼容。现在校验固定版本、锁记录和唯一入口后，
   用 Node 启动真实路径，避免再次下载。新原生盲测实际完成两次查询。
6. **PyPI MCP 接入。** 使用已有 uv/Python，在背包内创建独立环境，安装固定版本的二进制 wheel，
   不执行源代码构建或下载 Python；验证声明的 extras、入口及环境指纹。
   真实安装发现 uv 不接受同时传入 `--no-build` 与 `--only-binary`，已修正，模拟测试此前漏掉此兼容性问题。
   修正后实际安装了 29 个依赖包并启动入口。该次发布包随后因自身依赖兼容问题退出，仍判失败。

来源格式依据 [Claude 市场说明](https://code.claude.com/docs/en/plugin-marketplaces)、
[官方 Registry API](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/api/official-registry-api.md)
与 [uv CLI](https://docs.astral.sh/uv/reference/cli/)。本机问题与结果以实际日志、回执和产物为据。
完整候选集合只针对指定查询内的完整分页；这不是对整个市场中文/同义词语义召回率的保证。

进程耗时合计 **2,088.825 秒（34.8 分钟）**；修复期间存在少量并行运行，
这不是从开始分析到结束上传的墙钟时间。受测 Agent 与 Jev 合计 **2,178,336 token**，
16 次原生完成回合及已启动 Jev 请求均取得 usage。缓存输入已经包含在输入 token 中，不重复累加。
费用未知；根 Agent 的分析、编码、编排、网络诊断和浏览器验收用量不在此数内。

时区单项从上一轮首测失败（144.550 秒、122,398 token），到 r6 通过（90.476 秒、171,820 token）：
本样本成功且耗时更短，但 token 更多。不能声称这轮同时实现了最高准确率、最快和最省。
成功的周报及交互页面没有重复执行；已完成或结果未知的业务操作没有重放。
所有失败 MCP 尝试均为零业务调用；r6 的两个查询分别验证纽约和东京，并非重放同一回执。

## 产物验收与剩余缺口

- **周报：通过。** 新 `internal-comms` 指导和资源真实读取；进展、下一步、风险及原始数字、负责人、期限一致。
  有 completed 使用记录，但缺 started 记录，保留这一追踪缺口。
- **主题：未通过。** 最终置信度 0.69 低于 0.7，未取得新 Skill 或产出。未为过线降低最终阈值或指定名称。
- **购物车审查：未通过。** 外部 `coderabbit` 包已能读取、识别；原生组件和登录条件未满足，未生成或伪装审查结论。
- **交互页面：通过。** 新 `playground` 插件先接入再读取 Skill/模板。根评估器在离线 Chromium 实际操作
  两个滑块、边界值、重置与剪贴板，周期公式、单位、JSON 一致，零页面错误、零外部请求。
  受测 Agent 的脚本检查与根评估器浏览器验收分开记录。
- **时区：通过。** 新 `io.github.MukundaKatta/timezone-mcp` 0.1.0 在背包安装后，两次 `convert_tz`
  回执均 completed，结果分别是纽约 `2026-07-01T09:00:00-04:00` 和东京
  `2026-07-01T22:00:00+09:00`。独立 `zoneinfo` 校验日期、偏移和夏令时一致。
  DST 文字标签是 Agent 根据日期规则作出的解释，工具本身返回当地时间和偏移。
- **关系存储：未通过。** 最后一次自主选择了新 `vector-knowledge-graph-mcp` 1.0.10，
  其发布元数据只约束 `mcp>=1.0.0`，实际解析到 `mcp==2.3.0`；入口仍导入
  `mcp.server.fastmcp.FastMCP`，因此明确报 `ModuleNotFoundError`。
  隔离启动诊断复现同一错误，无业务调用。没有为所有市场包强行降级 SDK，也未改发布者代码。
  原始事实的复述不算保存或重新查询。要使这个具体包工作，还需要上游依赖约束修复或有依据的包级兼容方案。

PyPI 的声明 extras/入口规则有回归覆盖；真实安装成功样本没有使用 extras，因此不能声称 extras 的完整真实 MCP 流程已通过。
当前证据也不足以证明所有可用能力都不会漏选；目录阈值、功能词搜索和市场质量仍有明确限制。

## 保存、保护与检查

六个保护文件在本轮每次原生测试前后均一致：全局 Codex 配置及日常背包的公开授权、
外部来源、MCP 注册、路由、provider 配置。日常安装名单本轮没有新增或删除。
所有运行使用隔离副本，未改原工作区或 standalone 依赖中的未提交代码；日常网关没有更新。
测试用 MCP 服务已逐个按精确数据目录关闭并确认进程退出，浏览器已关闭；缓存、产物和回执保留，未删除。
原始日志、登录副本和不透明回执仅保存在本机私有证据目录，未上传公共仓库。

最终相关回归 64 项通过；完整回归 434 项通过、3 项可选检查跳过。
检查包含：撤权/中断不重放、候选不静默丢弃、插件宿主清单、外部固定来源、npm 真实主入口、
PyPI 参数/入口/环境篡改、选择阈值和注册表保护。项目必需文件、目录 JSON 和 `git diff --check` 另行通过。
本次是本地源码及隔离原生流程验证，不是日常 Agent 安装版验收。
