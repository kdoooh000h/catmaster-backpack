# 保留目录修正，减少重复展开：同批 14 题对照

保留上一轮修正后的目录说明，移除新候选的边界复核路径，复用已有自适应选择器。
同一时段重新运行描述修正版与精简版，两组均 **14/14 不遗漏且选对**；精简版平均
token 降低 **51.35%**，平均选择时间降低 **29.89%**。最终门槛仍为 **0.7**。
这是已知题目的单轮回归结果，不能证明所有新需求都不会遗漏。日常 0.3.73 未升级。

## 条件与结果

固定同一批原始中文、同义词及中英文混合需求，包括 12 条正向需求和 2 条引用/取消
控制；不指定能力名称、不注入固定英文摘要。固定 376 项公开能力、207 个目录节点、
目录成员、修正后的目录文字、原始终选全文、终选顺序和问题。源目录快照来自
`alirezarezvani/claude-skills` 的 `19392f7a08264ed00486a251f5b2098321771f94`。

目录门槛保持 0.2 → 0.3 → 0.4 → 0.45，最终 Choice 保持 0.7。目录可同时保留
多个分支；当前任务及明确要求的后续任务必须全程保留所需能力。每条需求交替运行
两组全新无状态调用，先冻结再测试，无调参、重试或历史模型回答复用。

| 指标（全部 14 题） | 描述修正版 `repaired` | 精简版 `slim` | 变化 |
|---|---:|---:|---:|
| 不遗漏且选对 | 14/14 | 14/14 | 持平 |
| 错误接受 | 0 | 0 | 持平 |
| 平均 token | 13,482.8 | 6,559.9 | −51.35% |
| 平均选择时间 | 3.563 秒 | 2.498 秒 | −29.89% |
| 平均调用次数 | 4.71 | 3.57 | −24.24% |

仅看 12 条正向需求，两组均 12/12：平均 token 14,515.3 → 7,472.4，降低
48.52%；时间 3.653 → 2.808 秒，降低 23.11%；调用 4.92 → 4.00。收益不只
来自两条控制提前退出。控制在精简版均只需一次目录判断，原修正版分别需 4 次和
3 次调用。多任务题保留了后续 SQL 能力，并先选数据质量能力，终选置信度为 0.86。

两组累计 116 次真实 Jev 请求、280,598 个报告 token、84.893 秒有效运行时间，
低于冻结的 196 次 / 450,000 token / 360 秒上限。116 份发送记录逐一对应完成回执，
无传输失败、未知发送或缺失用量；全部 28 行计入结果。总运行时间包含少量调度开销，
与逐题时间总和略有差异。

## 哪些地方变简单了

1. **目录文字原样保留，判断更明确。** 恢复已有选择器的“是否直接支持用户明确
   要求的操作”问题及规则引用，包含中文、英文、同义表达和必需的后续工作；仅仅
   背景相关、引用或已取消的任务不算需求。没有删掉数据质量、会议和研究摘要的范围修正。
2. **小分支整支保留。** 某分支已缩小到不超过 8 项时，保留全部成员给终选，其他
   大分支继续细分；不再重复读取这个小分支的子目录说明。这不是挑出前 8 项或截断候选。
3. **沿用已有提前终选规则。** 总候选不超过 24 项，或不超过 48 项且继续看目录
   的估计阅读量达到终选的 65%，进入终选。最多 6 轮目录，终选上限 96 项；超限
   明确停止，不回退全量。这些数值与被复用的原自适应实现相同，没有测试后调参。
4. **新候选无边界复核。** 不再额外问一次被淘汰的边界分支。旧复核实现仅保留在
   历史实验中，以便复现旧结果，不在精简版调用路径中。

本轮 `repaired` 基线也关闭边界复核。因此上表衡量的是**在已经去掉复核的基础上**，
明确请求判断和小分支保留的组合收益。没有重跑旧 `repaired_boundary`，也没有把
上一轮不同时间的延迟当作本轮对照。组合因素尚未单独消融。

实际观察：

- 第一层平均剩余候选 260.0 → 176.3；累计展示目录卡片 664 → 300（跨调用累计，
  不是不同目录数）。正向需求终选平均候选 23.0 → 19.1。
- 目录调用 52 → 38，目录 token 143,924 → 60,066；终选调用 14 → 12，终选
  token 44,835 → 31,773。两组边界复核均为 0 次。
- 耗时不是每题都下降：发布说明题 2.061 → 3.740 秒，尽管 token 9,299 → 5,370。
  终选阶段累计传输时间 9.012 → 10.023 秒；总时间减少主要发生在目录筛选阶段。
  单次网络和模型采样波动仍存在，不作统计显著性结论。

## 验证与保护

先通过 20 项受影响的离线检查，再运行实测。检查覆盖整支保留后续必需能力、避免
重复子目录披露、禁用基线复核、0.7 接受/0.69 拒绝、未知结果停止、不重试，以及
语义失败不得移出分母。新脚本仅组合已有选择器，不引入第三套路由实现。

分析器改为从冻结计划读取方案列表，以同时支持旧三组和新两组。旧完整三组结果重新
分析后，逐行结果、指标、阶段用量及失败均与原报告一致；这只是本地分析，没有发送模型请求。
真实回执再次验证原始需求、终选全文、输入和选择器哈希，以及未发生边界复核。

354 个已知发布/配置文件与开始快照一致，包含日常 0.3.73 热升级文件。主工作区和
生命周期工作区的 304 个已跟踪文件、HEAD 及 Git 状态一致；没有安装、激活或改写
运行目录、dispatcher、私有目录或生命周期功能。文件核对不替代另一对话的运行时验收。

结果只覆盖 Jev 选择器的报告 token 和选择时间；主 Agent 推理、协调、完整任务执行
成本、后端模型版本和金额不可观测。未重跑已通过的 Skill 产物、插件或 MCP 执行题。
本轮支持把精简版保留为后续候选，不等于日常发布或未知需求验收。
