# 第三层依赖审查修正与自适应停止对照

原来的“当前做文化、之后审依赖”本次修正后通过。只补描述的方案在这七条需求上
**7/7 选对且不遗漏**，旧方案 5/7，提前停止方案 6/7。保留描述修正作为后续实验
基线；提前停止方案不满足完整通过条件。整体 token 降低尚未实现，也未升级日常版本。

## 自适应的是什么

这几轮使用自适应展开：小分支整组保留，按剩余候选数量和阅读成本决定是否继续读下一
层、何时终选。它不是动态降低置信度要求。三个方案的门槛都相同：

| 层级 | 保留/接受门槛 |
|---|---:|
| 第一层 | 0.2 |
| 第二层 | 0.3 |
| 第三层 | 0.4 |
| 第四层及以后 | 0.45 |
| 最终选择 | 0.7 |

当前步骤优先终选、最多 6 轮目录、终选最多 96 个候选、原始需求与能力全文均不变。
日常已安装连接未在本轮修改或重新验证；这里描述的是隔离实验的选择器。

## 查到的问题和三组处理

原第三层把依赖审查、代码安全、环境密钥、Vault 和发布检查合在 123 个字符里。
它写了“审计依赖”，却没有说明依赖审查包括什么。先前失败分数为 0.35，本轮旧方案
重新采样为 0.39，都低于第三层 0.4。当前文化能力仍选对，后续依赖能力在这一步丢失。

修正从公开能力原有说明补出第三方软件包的漏洞、许可证冲突、间接依赖风险和安全
升级规划，并保留代码安全、密钥和发布检查的原范围。上层含有这段子目录说明的副本
同步更新。全部成员、父子关系及上一轮第一层文化修正不变。

| 组别 | 唯一变化 |
|---|---|
| 旧方案 | 上一轮文化修正＋当前步骤优先，作为基线 |
| 只补描述 | 第三层依赖说明及其上层副本补足具体操作 |
| 补描述＋提前停止 | 同一描述；候选不超过 48 个时，继续读目录的估算成本达到终选成本的 35% 就进入终选，原来为 65% |

最后一组的 35% 是**阅读成本比例，不是置信度门槛**。停止时将当时全部候选交给终选，
不裁掉候选、不缩短终选全文。比例是根据已有回执提出的待验证启发式，并非数学最优值。
旧失败路径的最后一次目录调用花了 2,137 token，只将候选从 39 减到 34，说明有必要
检验这次展开是否值得；不能预先把估算当作实际节省。

## 冻结的实测

原失败项的需求与答案保持不变，加六条新组合：知识库后审依赖、账户健康后审依赖、
欢迎邮件后审依赖、公司财务后审依赖再做知识库、当前审依赖后核算渠道，以及取消依赖
审查但仍做监控和账户健康分析。包含中文、同义表达、中英文混合及三步任务，不指定
Skill 名称或固定英文摘要。既有通过题没有重跑。

七题三组各一次全新调用，逐题轮换组别顺序。上限预先冻结为 147 次请求、420,000
token、360 秒；不重试、不在看到结果后调参或改答案。所有失败保留在分母中。

| 指标 | 旧方案 | 只补描述 | 补描述＋提前停止 |
|---|---:|---:|---:|
| 当前选对且全部必需能力全程保留 | 5/7 | **7/7** | 6/7 |
| 全程保留全部当前/后续参考能力 | 6/7 | **7/7** | 7/7 |
| 平均报告 token | 17,296 | 18,872 | 17,120 |
| 平均选择时间 | 2.921 秒 | 2.920 秒 | 2.852 秒 |
| 平均调用次数 | 4.86 | 5.00 | 4.71 |
| 总报告 token | 121,075 | 132,103 | 119,843 |
| 总调用次数 | 34 | 35 | 33 |

只补描述方案平均 token 增加 **9.11%**，时间基本持平。提前停止的表面低消耗不能当作
等价收益，因为它有一题未进入终选。三个方案都通过的五题，token 合计为
90,376 / 88,962 / 90,084，时间为 15.346 / 14.331 / 15.470 秒；这是事后参照，
不替代完整结果，也不能把采样路径差异当作稳定优化。

实际共 102 次请求、373,021 token、60.875 秒，21 行结果完整，低于冻结上限。
没有传输失败、未知发送、缺失用量或重试。成本仅统计 Jev 选择，不含主 Agent、意图
入口或业务任务执行。置信度是提供方分数，未经真实正确率校准。

## 原遗漏恢复与新限制

原失败项的依赖目录分数为 **0.39 → 0.43 → 0.43**。只补描述方案保留依赖能力，
最终仍以 1.00 选中当前文化能力。0.43 距离门槛只有 0.03；这次通过不能证明所有
问法都稳定。提前停止在这题少读一层，保留 44 个候选而非 39 个，仍选对当前能力；
token 为 12,889，比只补描述的 14,485 少，但这个单题收益不替代整组验收。

新增三步题“公司财务 → 依赖审查 → 知识库”暴露了终选数量限制：旧方案和提前停止
方案均保留 99 个候选，超过 96，于是没有发送最终选择请求；只补描述方案保留 93 个，
以 0.96 选中公司财务参考能力，所有后续目标也保留。

**这不是提前停止规则触发造成的。** 该路径候选一直大于 48，规则从未触发。两组
在第三层给产品研究目录的分数是 0.38 和 0.41，跨过 0.4 后多留下 6 个成员，导致
93 与 99 的差别。用只补描述组的已有回执逐步离线核对提前停止代码，五个请求的规格
和状态完全相同，得到同一结果；新增网络调用为零。这只是代码与路径诊断，不计作
新的通过样本，不替换提前停止组真实失败记录。

本轮因此保留完整通过的描述修正，整体节省 token 的要求仍未达成。提前停止代码和
失败证据保留在实验中，尚不作为后续默认策略；没有调高终选数量上限、降门槛或补跑。

## 验证与隔离

9 项离线检查通过：修改范围、原对象与成员保留、旧 65% 成本比例与原遍历一致、
提前停止保留完整候选池、当前步骤问题与原始需求一致、各层门槛不变、历史题排除、
未知结果停止，以及三组语义失败保留。另核对新遍历源代码与旧版本仅在成本比例参数
及其校验上有差别；旧文件和历史结果没有改写。

实测后核对 102 对回执、19 次实际终选、两次未发送终选的数量限制失败、连续调用
序号、逐行判分、token、冻结源码与输入、完整需求和候选描述。验证时 354 个发布/
配置文件、主工作区 232 个文件、另一生命周期工作区 224 个文件、其 HEAD 和 Git
状态均与本轮开始时一致。没有安装、激活、私有目录或生命周期改动。

这是实现者编写并预先冻结的七题、单次模型采样，没有独立盲测。说明的是公开目录
选择和保留情况，不是所有需求准确率、市场安装、插件/MCP 执行或日常版本验收。
模型后端版本、实际金额和完整主 Agent 成本在本次对照中不可观测。
