# Git 备份与恢复：2026-10-12

## 原因与修复结果

原生 Git 曾报告 `pack is far too short`、`bad object HEAD`。随后发现项目放在
受 iCloud Drive 管理的 Documents 目录中，出错的 144685 字节 pack 带有
macOS `dataless` 标记，实际数据块尚未落地。本次发现主目录 452 个、旧维护工作区
62 个这类文件。下载请求后，它们全部转为本机可读文件。

Apple 说明了 [dataless 文件与本地物化](https://developer.apple.com/documentation/technotes/tn3150-getting-ready-for-data-less-files)，
以及 [将 iCloud 文件夹保留下载](https://support.apple.com/en-euro/guide/mac-help/mchl1a02d711/27/mac/27)。
这次结论还由本地直接检查支持：原 pack 的 `PACK` 标头正常，其内容 SHA-1、包尾和
文件名的校验值全部一致。原仓库及独立取得的远端参考仓库 `git fsck --full` 均退出 0。
原仓库仍有 dangling tree/blob，已全部保留；这些对象不等同于损坏。

因此先前的“数据包损坏”判断已更正：本次故障是未下载的云端占位内容造成 Git
读取失败。恢复原文件后即通过完整性检查，没有替换历史或从远端覆盖本地代码。

另有一个长期遗留的空 `index.lock`。确认没有进程持有后，已将它移入备份隔离目录，
原字节和恢复入口保留。另一个同步产生的锁文件副本原样保留，没有进行清理。
Finder 已显示本项目“已保留下载”，File Provider 也回报 `isKeepDownloaded = 1`。
