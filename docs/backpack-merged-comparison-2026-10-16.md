# 多来源目录补齐与同五题对照

数据读取和原五条需求的对照已完成，但新的合并目录未通过“不遗漏”要求，不能替换
日常方案。排名只能帮助已匹配能力择优，不能恢复被目录提前删掉的能力。本轮没有
安装、连接、执行任何市场能力，也没有发布或修改日常版本。

## 数据补齐到了什么程度

- 原 589 项全部生成可检索索引。393 项至少一个分类 Choice confidence 达到 0.7；
  196 项保留已有分类分布中的可能标签作为宽松索引，不冒充已确认分类。
  最终能力选择门槛仍是 0.7。分类标签是索引，不是使用资格。
- 复用已安装 App 的公开榜单适配器和复制出的公开历史，接回 19 个本轮新读取的
  榜单视图。已捕获的新页面重新解析，不重复网络抓取，也不写日常排名缓存。
  45,325 个测试候选中，802 个匹配到可追溯的热度数据，756 个有七日增长数据；
  其余继续标为未知。仓库星标/增长不会被说成每个 Skill 的安装量，不相加不同来源
  计数，不直接比较安装量和星标。
- MCP 从旧第 34 页的原始游标续读，新增 412 次成功页面读取，最终共 446 页、
  44,551 条记录，游标为空，无重复内容冲突或同名多版本冲突。新增读取约 615 秒。
  500 条大分页试探未被接受，正式续读保留每页 100 条。没有重读旧 34 页。
  这是跨时间观察的目录普查，不是事务级实时快照；新增、更新的时效边界仍受源 API 限制。
- 原始 MCP 记录中 44,014 条满足官方 active 状态；加上已有参考源一项，形成
  44,015 个 MCP 候选。原 935 项合并目录中的独立 Skill/完整插件规则不变。

测试总目录为 **45,325 项：682 Skill、628 完整插件、44,015 MCP**。
其中 376 个 Skill 来自原公开实验库，明确标为历史对照，保留原参考目标，
**不计入已启用来源**；其余 44,949 项来自本轮公共来源记录。插件内部 Skill 依然
不单列，市场仍只作来源信息，程序去重继续保留所有别名和描述。

## 对照条件和实际结果

两组都使用同一份已合并/去重的目录、同一棵用途优先目录、原始五条中文/同义词/
中英文混合多任务需求、完整终选描述及最终 0.7。目录 Noul 门槛保持
0.2 → 0.3 → 0.4 → 0.45，保留当前步骤优先和后续必需参考目标。

基线将现有自适应选择逻辑用于这份新目录；候选组额外在同类、同计量单位中优先
考虑已观察热度和增长备选，仍保留未知数据候选，不按热度强删不同能力。
**这里的基线不是日常已安装路线的实测结果，不能说日常版本准确率为 0%。**

| 指标，五题各一次 | 新合并目录＋现有选择逻辑 | 同目录再加排名偏好 |
|---|---:|---:|
| 命中原当前步骤参考能力 | 0/5 | 0/5 |
| 当前参考正确且全部必需参考全程保留 | **0/5** | **0/5** |
| 平均 Jev CLI 调用耗时 | 5.060 秒 | 5.022 秒 |
| 平均报告 token | 27,595.2 | 32,788.4 |
| 平均调用次数 | 8.0 | 8.2 |

排名组 token **增加 18.82%**，耗时约减少 **0.75%**，且没有改善严格通过率。
每题只有一次采样，这点时间差不能当成稳定收益。时间统一取实际 CLI 回执之和，
不包含主 Agent、目录预处理、源读取或本地提示装配，不能冒充完整任务时间。

准确率按原来预先指定的参考目标计分。某些其他能力可能有部分相似功能，但未实际
执行来证明等价，不在结果出来后改判。例如依赖题选择了 supply-chain-risk-auditor，
其目录描述未明确覆盖原需求的许可证冲突；产品发现题选择了项目交付协调器 pm-skills，
没有命中原先的产品发现/RICE 参考。两组全部五题都在目录阶段丢失至少一项当前或
后续参考目标，因此无论这些替代项是否有部分帮助，都不能通过本轮严格验收。

## 为什么扩大目录后仍失败

1. **分类被填入索引，不等于分类质量已验收。** 196 项仍是暂定多标签，新增 MCP 中
   19,961 项只能保守进入所有大类。这样保留了目录覆盖，却削弱了筛选能力。
2. **细分摘要不能代表全部成员。** 第一版重复父级大范围说明，导致子目录几乎都
   相关，四行完成后即触及目录宽度/消耗边界。修正共同生成器、区分交付类型后，
   候选确实缩小，但只给少量代表能力的摘要仍会漏掉不典型成员。
3. **排名发生得太晚。** 正确能力已经被删掉时，给剩余能力加热度信息，只增加输入，
   无法补回目标。排名甚至可能让不完整的替代项更容易获得较高终选置信度。

当前证据支持先修正细分目录的完整覆盖表达，继续严格区分索引标签与最终使用判断。
它不支持降低 0.7，也不支持用榜首代替需求匹配。这一轮结果不作为日常升级依据。

## 全部消耗，没有丢弃失败成本

| 阶段 | 实际 Jev 请求 | 报告 token |
|---|---:|---:|
| 589 项分类维护 | 22 | 378,337 |
| 首版失败目录试验，含未完成行 | 27 | 261,407 |
| 修正目录后的完整五题两组 | 81 | 301,918 |
| **合计** | **130** | **941,662** |

分类最初的双面单选造成重复说明和分布输出；达到自设的 30 万预检预算后，原记录
追加到 40 万总预算，只对未处理条目使用一个主分类问题，并复用全部旧结果。
首版 A/B 的 26 万预算耗尽后保留全部失败。修正 A/B 的 16 万预算用完时已有四行
完成，随后在**同一记录**将总上限追加到 35 万，仅补齐原五题，复用六个已经完成的
阶段，没有重发已有请求或未知发送。这些是执行中的预算修订，不宣称成本上限全在
首次发送前就已固定。主 Agent、意图入口的 token、后端模型版本及金额不可观测。

## 验证和保护

30 项离线检查通过，覆盖游标续读/循环拒绝、相同输入才能复用、未知发送不重发、
同计量单位排序、过期排名处理、0.7 边界、全局候选数量约束和目录描述规则。
原始需求、输入/源码锁、130 个实际调用回执、判分、用量和完成状态已离线核对。
没有尚未核实的 pending 发送。检查通过只证明这些程序边界，不能抵消语义漏选。

本轮只修改隔离实验代码和报告。日常配置、源启用状态及安装内容未写入，另一升级
工作区未由本轮修改；保护核对结果记录在 JSON 中。
