# 插件/MCP 与两层目录合并验证

2026-10-12，公开项目源码已接入此前独立实现的插件/MCP 管道，并将选择入口
改为共用两层目录引擎。本地 Python 安装包候选版本为 `0.3.0`。

## 当前流程

Agent 提交需求 → 背包按任务大类、操作细类筛选 → Jev 选择具体能力 →
背包交付 Skill/命令说明，或通过 `invoke` 调用 MCP 工具/静态资源。

分类依据是已经登记的原始名称、描述、组件类型和 MCP 服务归属。
公开模板为 8 个任务大类、30 个操作细类，一个能力可归属多个细类。
目录缺失、当前可用能力未分类、描述变化或模板变化时停止选择，不省略能力，
也不退回全量选择。未完成分类且当前宿主不可用的组件，不阻断已覆盖的可用子集。

CLI `add` / `add --replace` 在登记后更新目录；未变化的元数据复用分类。
旧注册库可运行 `refresh-directory`。直接使用 Python `add_plugin` 的调用方
需要显式更新目录。新请求只选择，不重新分类全部能力。

新增、更新、停用、宿主连接和执行回执复用已有管道。原合并阶段的权限、会话、参数、
执行、重查和收尾函数与导入原实现的 AST 一致；这项检查属于本地自查。
后续合并审查补充了写入边界和动态参数校验修正，见末节。
两层选择引擎、目录校验和 Jev provider 与 `core/` 的三个公共实现逐字节一致。
详细接口、超时和置信度见 [连接协议](../core/plugin-connector.md)。

## 合并前审查修正

独立代码审查发现并修复了两处边界问题：

- 写入前按最终序列化的 UTF-8 字节数检查上限。注册库沿用 1 MiB，分类目录的全部
  写入步骤沿用自身 4 MiB 上限。超过上限时保留原文件及注册状态，避免写出不可再读取
  的数据；750 能力的大目录、变更刷新和超限保护均纳入回归。
- MCP 动态参数支持 `patternProperties`，显式字段约束和所有匹配规则共同验证。
  仅对未匹配的字段应用 `additionalProperties`，布尔子 schema 及无效表达式均有检查。
  正则使用现有 Python 引擎，不宣称完整 JSON Schema 或 ECMAScript 正则符合性。

修正经独立复审，没有剩余合并阻塞项。动态参数还通过真实本地 stdio 叶服务的隔离
协议流程验证：合法参数执行一次，非法字段在调用叶服务前拒绝。选择器和宿主为
模拟测试条件。这属于回归证据，原生日常 Agent 的业务调用证据仍属于前面的原合并版本。
合并检查在独立环境安装项目声明的可选 PyYAML 依赖，再执行完整测试及安装包验证。
仓库没有配置远端 CI；合并依据是记录的本地检查及独立代码审查。
