# 条件模糊检索后交给 Jev：原五题对照

检索能够绕过这批目录摘要的漏选，且显著减少选择消耗；终选仍只有 **2/5**
通过，不能替换日常方案。最终门槛保持 **0.7**，没有安装或执行业务能力。

## 参考 find-skills，哪些由程序做，哪些交给 Jev

核对了 Vercel 的公开 [find-skills 指导](https://github.com/vercel-labs/skills/blob/main/skills/find-skills/SKILL.md)
及 [find CLI 实现](https://github.com/vercel-labs/skills/blob/main/src/find.ts)：按具体任务搜索、
尝试替代表述、再核对候选。CLI 请求默认最多 20 项，并按安装量排序。官方仓库的
[搜索可见性问题](https://github.com/vercel-labs/skills/issues/1688)也说明，有页面不等于搜索能发现。
这里复用流程思路，没有运行或修改该 Skill，没有调用远程 Finder，也没有安装它。

本实验采用：

```mermaid
flowchart LR
    A[原始中文或混合多任务需求] --> B[程序按子句和中英词表检索]
    L[冻结的合并公开能力库] --> B
    B --> C[合并去重并保留各子任务候选]
    C --> D[Jev 一次判断当前应选的能力]
    D --> E{置信度至少 0.7}
    E -->|是| F[返回当前能力与保留候选]
    E -->|否| G[弃选并保留原始记录]
```

- **程序**：复用已有目录快照；SQLite FTS5/BM25 描述检索、中文二字切分、固定通用中英词表、
  英文拼写容错；各子句取前 8 项、命中的概念取前 3 项，再合并。完整插件始终是一条记录。
  描述别名也参与检索，市场名称、热度、历史对照身份和判分目标均不参与相关度。
- **Jev**：读取完整原需求、禁止事项、当前/后续顺序及候选完整描述，执行语义匹配和终选。
  不让主 Agent 再改写一个英文需求或逐个解释候选，也不让 Jev 负责确定性的去重和索引构建。
- **条件边界**：程序支持调用方明确传入允许的能力类型，并在检索前过滤。这五题没有显式类型
  限制，未把“只分析、不连接”猜成“删除所有 MCP”。自然语言限制交给 Jev；未验证自动提取硬条件。
  取消的事项仍可能被宽松检索召回，完整原文让 Jev 在终选时处理，避免程序误删。
- **召回边界**：排名截断处相同分数全部保留。合并超过 96 项会要求扩大处理，不强删到 96；
  没搜到返回“词面未匹配”，不冒充确认没有能力。单个子查询的前 N 检索仍可能漏掉语义目标，
  五题没有遗漏不构成普遍保证。本次只在离线参考覆盖全部通过后才发真实请求。

## 固定条件与低成本检查

复用上一轮最新的 **45,325 项**合并目录：682 独立 Skill、628 完整插件、44,015 MCP。
其中 376 个 Skill 为历史参考对照，另外 44,949 项来自已启用公开来源快照。
没有把市场中可发现、已经连接来源、已经安装和实际可执行混为一谈。
不重新抓市场，不拆插件内 Skill，不修改日常来源配置。

原五条中文、同义词、中英文混合需求保持字节相同；保留其当前及必需后续参考。
索引构建不接收判分标签，检索也只接收原始需求和公开元数据。固定通用词表在判分前写入，
没有能力 ID、指定仓库优先或逐题英文摘要；不过这是**已知开发题**，不能冒充盲测泛化。

先通过 12 项定向离线检查及原有 30 项相关检查，然后冻结输入、源码、CLI 和召回结果。
首次索引构建 **0.389 秒**，五次纯检索分别约 10–28 毫秒，调用 Jev **0 次**。

## 真实 Jev 选择对照

五题两组均重新执行一次，轮换组别顺序。共同保持相同目录、完整终选描述、选项顺序、
最终问题、原始需求与 0.7。自适应组沿用上一轮合并大目录的 10 轮上限、目录门槛
0.2 → 0.3 → 0.4 → 0.45、全局 96 上限和阅读成本停止条件；检索组直接使用检索候选终选。
没有同时改变提示词或按结果补参考候选。

| 指标，五题各一次 | 自适应目录 | 条件模糊检索 → Jev |
|---|---:|---:|
| 当前参考选对且达到 0.7 | 0/5 | **2/5** |
| 当前与全部必需后续参考全程保留 | 0/5 | **5/5** |
| 严格通过，须同时满足上两项 | 0/5 | **2/5** |
| 平均 Jev CLI 耗时 | 4.513 秒 | **0.630 秒** |
| 平均选择过程耗时，含检索和本地组装 | 4.609 秒 | **0.670 秒** |
| 平均报告 token | 26,637.2 | **4,967** |
| 平均 Jev 调用 | 7.6 | **1** |

报告 token 减少 **81.35%**，Jev CLI 耗时减少 **86.04%**，选择过程耗时减少 **85.46%**。
索引构建单列，未计入平均选择时间；整批五题只需构建一次。共同目录 JSON 读取、市场普查、
主 Agent、意图入口及实际业务任务耗时不在这里，不能把这些秒数说成完整 Agent 完成任务的时间。
后端模型版本、主 Agent token、意图入口 token 和金额不可观测。

这里的自适应基线是**现有选择算法用于这份新合并目录**，不是日常安装版的准确率。
严格按事前原参考目标判分，没有实际执行其他能力来证明等价，所以不改判替代项。

## 剩余失败与结论

通过的是渠道核算与先审查依赖两题，置信度分别 0.99、1.00。
其余三题均保留了全部参考，但终选未过门槛：

| 原需求简称 | Jev 原始首选 | 置信度 | 判定 |
|---|---|---:|---|
| 财务 → 依赖 → 知识库 | dependency-auditor，属于后续步骤 | 0.25 | 弃选 |
| 可观测 → 财务 → 文化 | observability-designer | 0.51 | 弃选 |
| 产品发现 → Jira | product-manager-toolkit | 0.53 | 弃选 |

后两题原始首选正确，但概率在多个候选间分散；产品发现题的原始分布约为产品工具包 0.54、
后续 Jira 0.43。字段 confidence 与概率分布分别原样保留，未互相替代。
这批证据把问题定位到终选的当前步骤判断和候选竞争；不能仅凭分布就断定全部底层原因。
本轮没有降低门槛、修改终选问题或追加重试。检索值得保留为实验分支，完整方案仍不发布。

总计 **43 次真实 Jev 请求、158,021 报告 token**：自适应组 38 次/133,186 token，
检索组 5 次/24,835 token。全部成功回执、原始输入、阶段保留集合和用量已核对，
没有未核实发送，没有重放。预设上限为 60 次/220,000 token/180 秒，没有追加预算。

主项目、另一升级工作区及已知日常配置的 **459 个文件**与 Git 状态前后相同。
仅隔离分支的实验代码、测试和报告改变；本轮没有日常升级、能力安装或插件/MCP 业务调用。
